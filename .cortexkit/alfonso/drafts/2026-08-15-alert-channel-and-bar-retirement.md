## acceptance_sketch


**Retired numeric bar**
- Byte-goldens prove that ordinary responses and `aft_inspect` responses contain no instance of the RETIRED BAR GRAMMAR (the former bracketed AFT health bar in its exact structural form), no `~` staleness marker in any AFT health rendering, no `status_bar` response-envelope field, no 15-call heartbeat, and no plugin-injected duplicate. THE ASSERTION IS GRAMMAR-SHAPED, NOT LETTER-SHAPED: a companion fixture proves that a diagnostic code such as `E0308` inside an alert line, and ordinary prose containing the letters E/W/D/U/C/T, remain legal — a token ban on those letters would contradict the alert contract and must itself redden. These goldens are scoped to the agent bar and alert channel; a NO-FREEZE arm makes any golden that freezes fleet-published TEXT fail while GATE-3 is open.
- Mutation arms restore each retired renderer or emit site independently, and each must redden at least one targeted golden: `formatStatusBar`, `statusBarLine`, `statusBarSuffixForSession`, `statusBarBlockForSession`, plugin `shouldEmitStatusBar`, the `force = true` render on `aft_inspect`, server `should_emit_status_bar` (with `status_bar_last_emitted`), and plugin `captureStatusBar` / `getStatusBar` / `lastStatusBar` on NDJSON and subc. `refresh_status_bar_counts` is deliberately excluded from deletion mutations: its separate fleet-feeder survival arm must redden if its Tier-2/todo values stop reaching `aft_status_segment`.
- REACHABILITY arm (obligation 1, and the reason the omission arm below is not vacuous): a static/instrumented arm asserts that NO caller of `AppContext::status_bar_counts` reaches agent-visible response text or the response envelope on any transport, and that `aft_inspect`'s payload is produced by `build_inspect_payload` rather than from that type. Re-wiring any surviving caller into `response_finalize`, `subc_format`, or the envelope must redden this arm.
- TYPE-SHAPE arm (obligation 2, SERVER side, SURVIVING consumers): unit arms pin that the `todos: tier2.todos.unwrap_or(0)` coercion and the all-or-nothing `(Some, Some, Some) => ... _ => None` aggregate gate no longer produce a silent zero OR a silent whole-aggregate suppression for the consumers that survive — a fixture with exactly one proven category must carry that category and omit the others, which the old gate could not do. A companion arm drives the same fixture twice so the `status_bar_cached` generation cache is exercised, asserting a cache hit reproduces the same omissions rather than resurrecting a zero or the whole-aggregate `None`. With no applicable or installed analyzer, neither the passive channel nor any agent-facing payload may fabricate `E0 W0`; Tier-2-unproven states omit D/U/C. Absence is asserted by optional-field absence, and a plugin fixture proves `parseStatusBarCounts` / `readNumber` do not coerce missing fields to zero on any path reaching a human overlay.
- **[GATE-3]** Fleet-values continuity (the byte-neutrality) arm, written now and branch-neutral: after the optional-type change, the retained `refresh_status_bar_counts` feeder still computes the same proven Tier-2/todo VALUES and passes them to `aft_status_segment`; the fleet text keeps those values because this writer survives, while any legacy coercion is asserted at the segment's call site. This arm deliberately does NOT compare fleet-published TEXT bytes or publish conditions. A separate NO-FREEZE arm rejects such text-freezing goldens while Gate 3 is open; when Gate 3 rules the human-lane text, its new text/omission contract receives its own golden.
- Fleet-publish survival: an arm asserts `aft_status_segment` is still published to the fleet plane, `holder_owns_status_bar` is still computed, and `refresh_status_bar_counts` still feeds its proven Tier-2/todo VALUES after the agent-envelope body is removed. Deleting `attach_status_bar` wholesale, disconnecting `refresh_status_bar_counts`, or deleting the `status_bar_counts` accessor must redden this arm. **[GATE-3]/[GATE-9]** the segment's own text honesty and the cross-root fleet-publish consequence of retiring `_aft_suppress_status_bar` are unruled; no arm asserts either outcome, and no campaign-wide honesty claim is asserted in CI until they land.
- **[GATE-4]** Pi `StatusBar`/`readStatusBar` and OpenCode `shared/status.ts::readStatusBar` + `tui/sidebar.tsx::collapsedHealthLights` are unruled. One arm is written now and is branch-neutral: neither overlay may render a clean/green state from an absent or unproven value. Survive, delete, or re-bind is decided later; absence-as-clean is forbidden under every branch.

**Alert channel**
- Silent baseline: a session opened against a fixture that already has errors, whose first authoritative observation precedes any this-session edit, renders no alert on that observation and none on a subsequent unrelated call. A companion arm proves the baseline observation SET `rendered` (not merely suppressed the render), by showing an identity present at baseline still does not fire on a later observation.
- Observation-source arm (pins the closed source list and specifically that the channel does not collapse to inspect-only): after a baseline observation, a session mutating-tool edit that introduces an error fires exactly one block with NO intervening `aft_inspect` call, driven by the post-edit verified diagnostics wait alone. A second variant drives source (iii) — a verified publish accepted for a root whose server is already live and quiescent — and also fires. A build in which only an explicit inspect can produce an observation reddens this arm. A negative variant proves a warming (pre-quiescence) report and a passive count read are NOT observations, and that the post-edit wait started no server on a cold root.
- PARTITIONING arms (a root-wide `live` set is a defect, asserted directly): on a two-server root, (i) an observation that accepts a document-version-verified snapshot from server A only updates A's partition and leaves B's `live` and `rendered` untouched — a build that substitutes a root-wide `live` will falsely mark B's identities `gone`, prune them from `rendered`, and re-page them on B's next publish, which this arm must catch; (ii) a post-edit wait with server B pending, exited, timed-out, or warming does not clear, prune, or otherwise mutate B's partition; (iii) a server first observed later does NOT flood its pre-existing diagnostics merely because another server baselined earlier — its own first observation is its own silent baseline; (iv) a multi-server observation finalizes as ONE ATOMIC BATCH containing exactly the producer partitions whose complete document-version-verified snapshots were accepted. A producer that completes and authoritatively finds zero errors writes an accepted EMPTY snapshot record and updates its partition; that record is distinct from a pending, warming, exited, or otherwise unaccepted producer's no-record. Pending, exited, timed-out, or warming producers are omitted from that batch and left untouched; no intermediate state of the terminal batch is observable from concurrent finalization.
- RECOMPUTED-NOT-QUEUED arm: an identity published and then REMOVED by a later authoritative observation before any eligible agent-visible response is finalized is NOT rendered, is NOT added to `rendered`, and — having been silently pruned — fires normally if it returns later. A queued-candidate implementation that renders an already-resolved diagnostic reddens this arm. At finalization, the fixture supplies a DISPATCH ROOT for the response and asserts the deliverable set is the union of `live − rendered` only across that session-and-dispatch-root's partitions; a coalesced block may span two producers in that root but cannot borrow or consume another root's state.
- First-observation branch arm, exactly one of two, never both green: DEFAULT branch — a fixture that edits a diagnostics-bearing file and then takes its FIRST authoritative observation of that partition renders NO alert for the newly introduced identity, which is in `rendered`, and the error is reachable only via `aft_inspect` (the accepted residual, asserted rather than discovered); **[GATE-10]** KEEP-STORE branch — the same fixture renders exactly one block with the your-edit clause, and every non-attributable identity present in that partition is still baselined. The fixture names which branch it encodes; a branch flip without a recorded ruling is a contract violation.
- Silent prune and re-entry: an identity that leaves `live` and later returns fires again exactly once; a mutation that keeps pruned identities in `rendered` must redden it. Disappearance or recovery alone renders nothing.
- Identity normalizer: a unit arm runs the single named normalization function against a fixed table (first line, trim, whitespace-run collapse, NFC — and nothing else). Table entries prove that path rewriting, numeric elision, and quote folding do NOT occur; adding any of them must redden.
- **[GATE-10]** Attribution, three arms, mutation-proofed both directions. Every arm expecting a block after an edit FIRST performs an authoritative observation of the SAME PARTITION that establishes the baseline (asserted in the fixture, including that `baseline_established` was set), THEN applies the causative mutation. (i) a session mutating-tool edit introducing an error renders exactly one `<system-reminder>` block on the FIRST AGENT-VISIBLE response after that diagnostic is published — not necessarily the next one after the edit — with file:line, first message, and the your-edit clause; (ii) an external/bash-mediated or watcher-only mutation of the same file renders the same block with NEUTRAL wording and no clause; (iii) an unrelated call with no session-new error renders no block at all. Arms (i) and (ii) require a session-scoped last-mutating-tool + DOCUMENT-VERSION store; document version is the only post-edit anchor and an epoch is not a diagnostics fallback. If the spike finds no store and the owner does not build one, (i) and (ii) are REWRITTEN to the neutral-only form and the your-edit clause is deleted from copy and goldens; they may not be left green by asserting on document version alone.
- **[GATE-10]** Analyzer-lag arm: after baseline, a diagnostic published three eligible tool calls after the causative edit still alerts and still attributes (document version >= mutation version). Forcing a longer lag must not change the rendered clause or select a later ride. Withdrawn with the clause under the drop branch; the alert-still-fires half survives either way.
- Coalescing arm: two or more new identities accumulated between renders produce exactly ONE block, ordered newest-first by the session-global observation ordinal in which each entered `live` (ordinals span producer partitions, so a two-server coalesced block still has one total order), with same-observation ties broken by the canonical identity tuple (asserted by a fixture in which two identities enter in the SAME observation, so a non-deterministic order reddens the byte-golden), with the exact `(+N more)` count of UNSHOWN identities, within the exact 3-line cap (at most 2 alert lines plus the `(+N more)` line, excluding reminder tags). Assert block count == 1 and that the next unchanged response is silent. Every identity represented by the finalized block, INCLUDING those counted only by `(+N more)`, is asserted to be in its owning partition's `rendered` afterwards.
- Truncation arm: a single over-long diagnostic yields exactly one block, one line, ellipsis-truncated at the fixed maximum line length, never wrapped. **[GATE-6]** the constant, the unit it is measured in, and the ellipsis token are unruled (open_questions 6); the arm asserts the truncation PROPERTY now and pins the number, unit, and token in a golden once chosen.
- Re-emission arm: an already-rendered identity does not re-fire; reintroducing the 15-call heartbeat or the force-on-inspect render must redden a golden. A companion arm proves `aft_inspect` CARRIES a pending block like any other agent-visible response while never forcing one.
- Exclusion arm: internal/transport commands neither carry nor consume a pending alert — a pending block survives an excluded call and rides the next agent-visible response. The excluded set is asserted against a CLOSED list snapshotted verbatim into the fixture from today's attach exclusion list, not against whatever the code excludes at run time: an internal command outside the snapshot that neither carries nor consumes reddens the arm, so adding a command forces a recorded placement decision instead of drifting silently.
- Isolation arms, both directions: no cross-session and no cross-root bleed; alert state does not persist beyond the session (a new session against an unchanged tree re-establishes a silent baseline rather than firing). If a durable digest baseline store exists (open_questions 7b), an arm proves the alert channel does not read it.
- Cold-root silence arm: no analyzer running for the root plus an edit that breaks the build ⇒ no block, and specifically no rendered health-count token (`E0`, `W0`, or any other category token in the retired bar grammar) and no clean-state claim anywhere in the response. THE BAN IS GRAMMAR-SHAPED, consistent with the retired-bar goldens above: a diagnostic code beginning `E0` remains legal wherever an alert legitimately renders, so the arm keys on the count-token grammar rather than on the letter pair. The passive path is asserted to have started no server.
- Host-uniformity arm: byte-golden proves identical rendered block text on NDJSON, subc, and MCP text-only, with no host-side reformatting, no UI-metadata lane, and no second injection path, and never more than one reminder block on one response. A companion golden with the fleet line present on the same response proves the block renders byte-identical to its fleet-absent form and that the response contains no RETIRED health-count token shapes other than a fleet line that already contains them; the legal `(+N more)` suffix remains an alert-identity count — this is the testable meaning of COMPOSE.
- Trigger-set arm: a Tier-2 count delta or todo change with no new error diagnostic renders no block; the same delta is visible via `aft_inspect`. Warnings, info, and hints likewise never page this channel.
- Alert/aggregate split: no project-wide counts in the alert channel; `aft_inspect` remains the aggregate surface with its category set and `sections` contract unchanged.

**Delta engine, two consumers**
- Snapshot isolation, asserted in BOTH directions on the same fixture, across ALL THREE alert fields, and on EVERY producer partition: a `health.digest` call for a (session, root) never reads or writes `live`, `rendered`, or `baseline_established` in any partition — a later agent-visible response still fires the block for that identity, a digest call cannot itself establish a silent baseline, and a digest call cannot advance `live` so as to flood a later observation — and rendering an alert block never mutates any digest anchor. A shared mutable snapshot must redden both arms.

**`health.digest` (AFT-side slice only)**
- Not-an-agent-tool arm: no agent-facing tool definition is registered, the op never appears in tool-response text on any transport, and a digest call neither carries nor consumes a pending alert block. The op is reached by NAME (`health.digest`); the fixture keys on that name so a rename reddens rather than silently re-binding.
- Passive-bound arm: a digest call against a cold root starts no server, never blocks on quiescence, never triggers a cold build, and OMITS diagnostics rather than reporting zero or `~`.
- **Interim digest-value arms (BINDING NOW):** a digest value is admitted only with its category's freshness ticket and a conceptual `since` input, but no arm calls any value new, changed, resolved, or a delta relative to `since`. The arm exercises reusable identity, normalization, verification-or-omit, passive behavior, and consumer isolation now; it asserts FRESH TICKETED VALUES, not interval membership. A value without its ticket is omitted; it is never fabricated as zero, `~`, or an empty delta. Gate 7 does not block this interim digest behavior.
- **[GATE-7] Post-gate interval arms:** after Gate 7 rules the `{root, since}` wire encoding and delta semantics, each category arm proves BOTH its freshness ticket and membership in the ruled interval: current error diagnostics use an already-live DOCUMENT-VERSION-verified snapshot; Tier-2 values use stat-verified artifact identity and its artifact-generation EPOCH; TODO values use that same artifact; watcher values use accepted journal events with their accepting stat identity; and resolved diagnostics use the ruled durable baseline. Until then, no category is represented as a delta, including resolved diagnostics.
- Structured-fields arm: the reply carries no pre-rendered prose, no retired bar grammar, and no `~` marker. Ticketed numeric current values are permitted where a number is the datum, but a pre-gate fixture asserts only freshness and omits any delta label or interval claim; an assertion banning integers outright would contradict the structured-value contract and must itself redden.
- **[GATE-7] Delta-label/wider-trigger arm:** after Gate 7, a root with a live server, stat-verified Tier-2 data, TODO data, and a watcher summary proves that these digest categories are representable as interval deltas only when each is both fresh and in the ruled interval. Their interim ticketed current values are already binding; they never page the alert channel.
- **[GATE-7]/[GATE-8]** No wire schema, field name, `since` type/boundary, ordering, retention, restart-survival, or exposure/authorization behaviour is frozen in a golden. Conceptual `{root, since}` freezes neither encoding, field names, `since` type, nor root cardinality. No pre-gate fixture depends on an interval anchor; "delta-engine reuse" remains identity, normalization, verification-or-omit, and consumer-scoped isolation, never reuse of the session alert snapshot as a `since` baseline.

**Release-boundary copy**
- The alert-channel explanation is asserted to land on the ONE release boundary that carries the blocking-fresh inspect tool-description changes; `health.digest` introduces no agent tool-description change.

**Observation logging (mechanism in scope, outcome out)**
- TWO record kinds are constructed SERVER-SIDE, but durable writes are scoped NOW to OpenCode-hosted sinks. Other harnesses receive the same alert bytes and record schema construction, while a production sink, retention, write-failure behavior, and query surface for them are declared future behind **[GATE-11]**. (1) ALERT-RENDERED is written at finalization once PER IDENTITY represented by the finalized block, including identities counted only by `(+N more)`, carrying a shared **block id**, session id, dispatch root, producer key, tool-response id, diagnostic identity fingerprint, file:line, severity/code, attributed-vs-neutral form, SHOWN-vs-COUNTED-ONLY flag, the session-global `agent_visible_response_ordinal`, and lifecycle episode id. All rows for one block share its block id; the identity fingerprint plus lifecycle episode id is the per-row key. (2) DISAPPEARANCE is written when a previously rendered identity leaves `live` at an authoritative observation of its partition, carrying the same lifecycle episode id, session, root, producer key, and observation ordinal. Its `agent_visible_response_ordinal` is the ordinal of the NEXT finalized agent-visible response on which the delta engine observes and records that disappearance, never the asynchronous detection moment. A kind-(1) arm proves the complete row set for a rendered alert in an OpenCode-hosted sink, including one row for every counted-only identity in a coalesced fixture; a per-block-only implementation or omission of counted-only rows must redden it. A separate arm asserts kind (2) is measurement-only — it never renders and never pages the alert channel.
- Lifecycle arm: when an identity first appears in an authoritative observation, its lifecycle episode id is minted and stored in session delta state. Its episode closes on disappearance; if the same identity re-enters, a NEW id is minted. A repeated disappearance → re-entry → disappearance fixture renders both episodes, inserts exactly two non-rendering agent-visible responses between the first render and the second disappearance, and proves the two disappearance rows join only their matching render row. The fixture also proves that both record kinds use the one session-global agent-visible-response ordinal domain, that the disappearance ordinal is assigned at the next finalized observation response rather than detection time, and that the domain increments for every agent-visible finalization whether or not it carries a block.
- Record-source isolation arm: a `health.digest` call writes NO record of either kind, even when its structured reply contains ticketed current values. Kind (1) writes are confined to alert finalization and kind (2) writes are confined to authoritative observations that remove a previously rendered identity from its producer partition.
- The committed offline query computes "alert rendered → diagnostic resolved within N turns" with N fixed at 5 turns, joining kinds (1) and (2) on producer key plus lifecycle episode id, WITHOUT parsing rendered prose. The DISAPPEARANCE side counts its ordinal from the next finalized response on which the delta engine observes the disappearance, never from asynchronous detection; the fixture makes that response and its ordinal explicit. Its fixture includes both SHOWN and COUNTED-ONLY identities and the known non-rendering response gap, so it proves both populations are joinable in the shared ordinal domain. Dropping counted-only kind-(1) rows, recording only one row per block, or joining a re-entry to its former episode reddens the query arm. A build that omits kind (2) must instead name an EXISTING durable diagnostics-transition source and prove by fixture that it joins on producer and lifecycle episode id; an arm asserts that "a join key alone" does not satisfy this, by showing the query cannot be computed from kind-(1) records only. The `opencode.db` instance is ONE consumer of the records for the OpenCode measurement window, not their home.
- CI asserts the record SCHEMAS, per-identity granularity, the SHOWN-vs-COUNTED-ONLY distinction, episode separation, and that the query runs against the fixture; it does NOT assert the efficacy result. LEBENCH-style before/after evidence stays out of CI. **[GATE-11]** the non-OpenCode sink, retention, write-failure behavior, and query surface are unruled; no arm freezes them. ASSUMPTION ON RECORD: the campaign premise — event-shaped reminders are acted on where numeric trailers are not, and wake-from-dark is when orientation data is actionable — is falsified by no test here; owner, baseline dataset, measurement window, success metric, the sink for non-OpenCode sessions, and the response to a null result (revert the alert channel, revert the digest, or keep both on the honesty argument alone) must be named before ship.


## constraints


- **The delta engine is ONE component with TWO consumers, and what is shared is bounded.** SHARED AND BUILDABLE NOW: canonical error-diagnostic identity, the named normalization function, verification-or-omit, and consumer-scoped snapshot discipline. Consumer A is the AGENT ALERT BLOCK (in-context, session-scoped, errors-only, new-only). Consumer B is `health.digest` (a management-surface operation). The digest's interim contract is BINDING NOW: it returns only FRESH TICKETED CURRENT VALUES or omitted fields, never fabricated zero, `~`, or an interval/delta label. **[GATE-7]** rules ONLY the `{root, since}` wire encoding and the durable-baseline/interval semantics that permit new, resolved, changed, or delta claims; it does not block the interim digest slice or its tests. Consumer A's non-persistent state cannot be a digest baseline. SNAPSHOT OWNERSHIP IS CONSUMER-SCOPED: digest never reads or writes alert `live`, `rendered`, or `baseline_established`; alert rendering never mutates a digest anchor. A shared mutable snapshot is a defect.

- **Alert delivery is host-uniform and server-rendered (RULED).** AFT appends one `<system-reminder>` block to final response text on NDJSON, subc, and MCP. No UI-metadata lane, per-host formatter, or plugin-side renderer may produce the block. The hard cap is at most three rendered lines excluding tags: at most two alert lines plus a third line consisting solely of `(+N more)`. Ordering is newest-first by the session-global authoritative-observation ordinal in which an identity entered `live`, with same-observation ties broken by the canonical identity tuple. Each alert line truncates rather than wraps; **[GATE-6]** alone rules its maximum, unit, and ellipsis token. Finalization recomputes, rather than queues, the deliverable set as the dispatch root's union of `live − rendered`; it never consumes another root's state. Internal/transport commands neither carry nor consume a pending block, while `aft_inspect` carries a deliverable block but never forces one. Every represented identity, including a `(+N more)` identity, enters its owner partition's `rendered`.

- **Alert predicate and authoritative-observation state machine.** Candidates are ERROR-severity diagnostics only; warnings, info, hints, Tier-2 D/U/C, and todos never page. Identity is `(canonical root-relative file, range, severity, source/server, code when present, normalized first message)`. The one normalizer takes the first line, trims, collapses whitespace runs, applies NFC, and does nothing else. An AUTHORITATIVE OBSERVATION is acceptance of a complete DOCUMENT-VERSION-verified diagnostics snapshot (rust-analyzer after quiescence) for one live or explicitly inspected producer. Document VERSION is the sole post-edit diagnostics anchor for acceptance and attribution. Artifact-generation EPOCH is a Tier-2-only anchor, paired with stat-verified artifact identity; it is never a diagnostics fallback. Warming reports, passive reads, and digest calls are not observations.
  OBSERVATION SOURCES ARE CLOSED: (i) the existing post-edit diagnostics wait for a session mutating tool on an already-live root; (ii) diagnostics accepted by blocking `aft_inspect`; or (iii) a document-version-verified continuously-drained publish for an already-live, and when applicable quiescent, server. No timer, heartbeat, passive count read, or warming report may create an observation. State is per `(session, canonical root, producer key)`: `baseline_established`, `live`, `rendered`, and lifecycle episode ids. A root-wide `live` set is a defect.
  An update changes ONLY partitions with a complete accepted snapshot. A multi-server update is one atomic terminal batch of exactly those partitions. A producer that completes and authoritatively finds zero errors writes an accepted EMPTY snapshot record, updates its partition, and is distinct from a pending, exited, timed-out, or warming producer, which writes no record and leaves its partition unchanged. First observation silently baselines its own partition by setting both `live` and `rendered`; later observation silently prunes `gone = previous live − current`, closes each gone episode, and mints a new episode on re-entry. Disappearance and recovery alone never render. Under **[GATE-10]**, the KEEP-STORE branch may withhold from this first baseline only identities proven by a session-owned last-mutating-tool plus DOCUMENT-VERSION store; without that store, the default silent baseline is mandatory.

- **Attribution is document-version-anchored, not time-anchored (RULED).** The your-edit clause attaches only when the file's last known mutation belongs to this session's mutating tools and the diagnostic document version is at least that mutation version. An epoch is not an attribution fallback: artifact-generation epochs prove Tier-2 freshness only. If the document-version or ownership proof is absent, or another actor owns the last mutation, the alert is neutral. Analyzer lag does not select a later ride, and no wall-clock window exists. **[GATE-10]** decides whether the required session-owned mutation store is built; otherwise the clause and its positive goldens are removed and the default first-observation branch remains locked.

- **`health.digest` (AFT-side slice), verification-or-omit.** `health.digest` is a named management operation with conceptual inputs `{root, since}`; it is not an agent tool, never appears in tool-response text, and neither carries nor consumes a pending alert. Its BINDING interim reply is structured FRESH TICKETED CURRENT VALUES or omitted fields. Current diagnostics require an already-live document-version-verified snapshot; Tier-2 values require stat-verified artifact identity plus its artifact-generation epoch; TODO values use that artifact; watcher values require accepted journal events with accepting stat identity. It never starts a server, blocks for quiescence, or triggers a cold build. **[GATE-7]** subsequently rules only wire encoding and interval/delta semantics; Gate 8 rules exposure and authorization. Neither gate permits an unverified value or blocks the interim slice.

- **Absence-as-zero is killed at the type, not the formatter.** Surviving `StatusBarCounts` consumers read per-category OPTIONAL values: no proven value is absent, never zero; a cache hit preserves the same omissions. The `todos: tier2.todos.unwrap_or(0)` coercion and all-or-nothing `(Some, Some, Some) => ... _ => None` gate must not survive. There is no agent-facing consumer: no `status_bar` envelope, plugin renderer, plugin cache, or alert count. `aft_inspect` remains built by `build_inspect_payload`, not this type. A reachability arm proves no `status_bar_counts` caller reaches agent-visible text or an envelope; a type-shape arm proves a single proven category survives while unproven categories omit.
  **NO-FREEZE and Gate-3 are deliberately different.** Until Gate 3 rules fleet text, the NO-FREEZE arm fails any golden that pins fleet-published TEXT or publish conditions. The Gate-3 continuity arm instead pins the fleet segment's VALUES-computation chain: `refresh_status_bar_counts` supplies proven Tier-2/todo values, optionality stays intact until the segment's explicit legacy coercion point, and `aft_status_segment` receives those values. It deliberately makes no text-byte claim. When Gate 3 lands, a new fleet-text golden replaces these interim arms.

- **Fleet lane.** The human fleet line remains the other campaign's settled contract except Gate 3's AFT-segment omission/text ruling and Gate 9's cross-root suppress consequence. No campaign-wide honesty assertion or fleet-text golden is legal before Gate 3. Alert composition is nevertheless testable now: the alert bytes are identical with or without a fleet line, no retired token shape occurs outside that line, and `(+N more)` counts only unshown alert identities.

- **Observation records and efficacy query.** OpenCode-hosted sinks receive two server-constructed kinds: ALERT-RENDERED once per represented identity at finalization, including counted-only identities, and DISAPPEARANCE when a previously rendered identity leaves `live`. Both carry session, root/dispatch root as applicable, producer key, lifecycle episode id, and the shared session-global `agent_visible_response_ordinal`; rendered rows also carry block id, response id, fingerprint, location, severity/code, wording form, and shown/count-only status. ## intent


ATTENTION-MODEL CLAIMS ARE RATIONALE, NOT ACCEPTANCE. The assertions that agents skip passive numeric trailers, act on imperative event-shaped text, and find aggregates actionable at wake-from-dark are recorded assumptions (owner, measurement window, and null-result response are release gates — see open_questions 11). No test in this campaign falsifies them. The load-bearing justification that stands without them is the honesty argument: never render a number known stale, never render absence as zero, never render zero where no analyzer ran.

1. **The agent-facing numeric health bar is retired, and absence-as-zero is killed at the type.** The bar's agent renderers, its emit cadence (the 15-call heartbeat and the server-side emit-on-change gate), its `status_bar` response-envelope field, its force-render on `aft_inspect`, and its plugin renderers and caches are DELETED; the "Named retirement surface" bullet in constraints is the authoritative, locatable list, server side and plugin side. `StatusBarCounts` is CONVERTED to per-category optional values so a category with no proven value is ABSENT rather than zero — the mechanism, not the formatter, is where absence-as-zero dies. Downstream must read this as TWO obligations: REACHABILITY (after retirement no caller of `status_bar_counts` reaches agent-visible response text or the response envelope on any transport) and TYPE SHAPE (the surviving consumers — the fleet segment, and whichever human overlay survives open_questions 4 — read optionals, so one proven category is carried while the unproven ones are omitted). This move does NOT retire the human lane: `attach_status_bar` may not be deleted wholesale because it also publishes `aft_status_segment` and computes `holder_owns_status_bar`; while **[GATE-3]** is open, fleet-published TEXT is deliberately NOT frozen and only its VALUES-computation chain is pinned. The fleet-publish consequence of retiring `_aft_suppress_status_bar` is open_questions 9 (**[GATE-9]**), and the Pi overlay and OpenCode sidebar lights are open_questions 4 (**[GATE-4]**).

2. **Event-shaped alerts replace the retired numeric bar.** The agent-facing numeric bar is DELETED. In its place, the **agent alert block**: one server-rendered `<system-reminder>`-tagged block appended to tool-response text, byte-identical on NDJSON, subc, and MCP (RULED: no per-host formatter, no UI-metadata lane). It renders ONLY when an error-severity diagnostic is a session-new candidate under the predicate fixed in constraints, carrying file:line and the first message — never health counts. (The `(+N more)` coalescing suffix is a count of unshown ALERT IDENTITIES, not a health aggregate, and is not covered by the never-counts rule.) Attribution to the agent's own edit is DOCUMENT-VERSION-ANCHORED, not time-windowed (RULED); an epoch is reserved for Tier-2 artifact generation and is not a diagnostics fallback. It degrades to neutral wording when document-version/ownership evidence is absent or another actor last mutated the file; the session mutation-ownership STORE the clause requires is not evidenced today and is open_questions 10 (**[GATE-10]**), whose ruling also locks the first-observation branch. Trigger set is ERROR-DIAGNOSTIC DELTAS ONLY: Tier-2 counts and todos never page this in-context channel; mid-task they are reachable only by an explicit `aft_inspect` call, and at wake by the health digest (move 3). Silence is the default and the honest output.

3. **Since-anchored health digest (second consumer of the same delta engine, management surface).** The delta machinery built for move 2 — canonical error-diagnostic identity, a conceptual `since` baseline, and the provably-fresh-or-omit rule — gains a SECOND consumer: `health.digest`, a management-surface operation conceptually identified by `{root, since}`, discovered by op name and consumed by the dark-wake composer as an ordinary client. It is NOT an agent-facing tool, is never appended to tool-response text, and is never consumed in-context. It carries only ticketed current values and omits the unmeasured; the passive no-server-start bound applies, so a cold root's digest omits diagnostics rather than starting an analyzer. Its trigger set is DELIBERATELY WIDER than the alert channel's (error diagnostics, Tier-2 values, TODOs, and watcher summaries, with resolved diagnostics once a durable baseline exists) — the shared law is verification-or-omit, not a shared trigger set. Gate 7 is the destination only for that wider set's wire encoding and interval/delta semantics: until it rules `since`, its baseline, and interval membership, no value is represented as new, resolved, changed, or a delta relative to `since`; the AFT-side digest slice and acceptance assert FRESH TICKETED VALUES now. Conceptual `{root, since}` freezes neither encoding, field names, `since` type, nor root cardinality. In scope here: the AFT-side op, its reuse of the delta engine, and its fixtures. Out of scope: the dark-wake event, the wake composer, prefrontal's composition, PLEX's GitHub lane, and all holder-side rendering. A durable `since` history is not an implementation prerequisite for the binding interim values; Gate 7 may define it only for later delta behavior.

FOUR surfaces are named and must not be conflated downstream: (1) the RETIRED NUMERIC BAR (agent-facing E/W/D/U/C/T tokens and their render paths), (2) the AGENT ALERT BLOCK (this campaign's in-context channel, AFT-owned and byte-identical on all harnesses), (3) the HUMAN FLEET LINE (the other campaign's settled contract, including `aft_status_segment` until open_questions 3), (4) the WAKE HEALTH DIGEST (`health.digest`, management-surface, composer-consumed, explicit pull, never ambient). Remaining human count UIs that read the same snapshot (Pi overlay, OpenCode sidebar lights) are none of these four and are parked in open_questions 4.

## glossary

- **Retired numeric bar:** the former agent-facing bracketed AFT health rendering and its E/W/D/U/C/T count-token grammar, response-envelope field, heartbeat, plugin renderers, and plugin caches. This does not name the fleet line or the legal `(+N more)` alert-identity suffix.
- **Agent alert block:** the server-rendered, `<system-reminder>`-tagged, errors-only block attached at finalization to one agent-visible response. It is a session-scoped consumer of the delta engine and is never a count aggregate.
- **Dispatch root:** the canonical root of the response currently being finalized. It is the only root whose partitioned alert state can supply or consume that response's `live − rendered` set.
- **Producer partition:** state keyed by `(session, canonical root, producer key)`. It owns `baseline_established`, `live`, `rendered`, and each identity's lifecycle episode state.
- **Authoritative observation:** acceptance of a complete document-version-verified diagnostics snapshot for one producer partition, including an accepted EMPTY snapshot when it authoritatively finds zero errors. Warming reports, passive reads, digest calls, and no-record producers are not observations.
- **Lifecycle episode id:** a session-delta-state identifier minted when an identity first appears in an authoritative observation, closed when it disappears, and replaced by a new id if the identity re-enters.
- **Freshness ticket:** category-specific evidence that a current digest value is trustworthy. It is not interval membership and never, by itself, proves that a value is new, resolved, changed, or a delta.
- **Conceptual `{root, since}`:** the logical digest input pair. It does not freeze wire encoding, field names, `since` type, root cardinality, ordering, retention, or exposure.
- **OpenCode-hosted sink:** the only durable observation-record sink in scope now. Non-OpenCode durable sinks are future work under Gate 11.

## design

The design has two isolated consumers. The alert consumer observes verified error diagnostics per producer partition, silently baselines each partition's first observation, silently prunes a disappeared identity, and recomputes delivery from the dispatch root at finalization. It emits at most one ordered reminder block per eligible response. The alert consumer has no queue, no heartbeat, no force-on-inspect path, no cross-root borrowing, and no persistent state beyond the session.

The digest consumer is a management-surface operation rather than an agent tool. It reuses canonical identity, normalization, verification-or-omit, and consumer isolation. Its AFT-side interim behavior is binding now: ticketed fresh current values or omissions. Gate 7 later rules only `{root, since}` encoding and interval/delta semantics; every delta category then proves both a ticket and ruled interval membership. Digest reads never establish an alert baseline, advance alert `live`, consume a pending alert, or write an observation record.

The retired bar is removed from agent-visible responses without deleting the fenced fleet lane. `attach_status_bar` may be edited now to remove the agent-envelope insertion and preserve the current fleet publish. Gate 9 decides only the env-specific cross-root fleet-suppression behavior. The fleet compose golden bans retired health-count token shapes outside the fleet line while preserving `(+N more)` as a count of unshown alert identities.

Observation records are constructed at the server-side alert events. Each finalized alert block produces one ALERT-RENDERED record per represented identity; a disappearance produces a DISAPPEARANCE record only when the identity had been rendered. Its ordinal is assigned to the next finalized agent-visible response on which the delta engine observes disappearance, never to asynchronous detection. Both records use the same session-global ordinal domain and lifecycle episode id. The five-turn query joins on producer key plus lifecycle episode id, never rendered prose. Durable writes are limited to OpenCode-hosted sinks until Gate 11 names the other harnesses' sink and failure behavior.

## interfaces

- **Alert finalization interface:** finalization receives or derives exactly one dispatch root. It queries only that root's producer partitions, appends at most one server-rendered reminder block, marks every represented identity rendered in its owner partition, and emits per-identity record events to the logging interface. No other slice edits `response_finalize.rs`.
- **Observation-update interface:** an accepted snapshot is supplied as `(session, canonical root, producer key, document-version-verified identities)`. A multi-server terminal update is one atomic batch containing exactly accepted producers; an accepted zero-identity producer emits an accepted EMPTY snapshot record, while pending, exited, timed-out, and warming producers emit no record and remain unchanged. The update returns lifecycle opens/closes and current state for finalization without exposing a root-wide `live` set.
- **Digest interface:** `health.digest` is addressed by name and has conceptual inputs `{root, since}`. Before Gate 7, its logical output is ticketed fresh current values or omitted fields; it has no frozen wire schema or delta vocabulary. After Gate 7, the interface must prove ticket plus ruled interval membership for every delta-bearing category. Gate 8 owns registration, authorization, and transport exposure.
- **Observation-record interface:** an alert event supplies block id, dispatch root, producer key, identity fingerprint, lifecycle episode id, shown/count-only status, and `agent_visible_response_ordinal`; a disappearance supplies the same episode and the ordinal of the next finalized response on which the engine observes it, never an asynchronous-detection ordinal. The OpenCode-hosted sink accepts these schemas now. A future harness sink is not implied by construction of the event.
- **Fleet-composition interface:** retirement code preserves `aft_status_segment` publication, `holder_owns_status_bar`, and the `refresh_status_bar_counts` values feed through named surviving seams. Until Gate 3, no golden freezes fleet TEXT; the Gate-3 continuity arm observes only the VALUES-computation chain, while the compose golden observes the alert around the fleet line without redefining it.
