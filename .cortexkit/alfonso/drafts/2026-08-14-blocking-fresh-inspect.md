## intent

Agents ignore AFT's code-health surface, and the design premise of this campaign is that they are RATIONAL to: the status bar shows stale counts with a `~` disclaimer, renders analyzer-absence as `E0 W0` (absence-as-zero), and serves project-wide aggregates (the D797-class glance) that are never actionable for the current task. Meanwhile explicit `aft_inspect` returns cache-with-disclaimers ("provisional", "pending_categories") instead of mechanically verified tree state.

This campaign separates authoritative inspection from passive notification; the wake-digest surface is specified by the alert-channel-and-bar-retirement campaign.

1. **Blocking-fresh `aft_inspect`.** An explicit inspect call produces exactly ONE terminal response and no progress frames (RULED). A SUCCESSFUL terminal response contains only category data mechanically verified against the inspected tree: diagnostics accepted only after the applicable server publishes a version/epoch-verified result and, for rust-analyzer, after its quiescence signal; Tier-2 accepted only after stat-verification proves the persisted artifact matches the current tree, or after the required callgraph/Tier-2 build completes and publishes. Servers are started on demand (bounded, reaped after idle) and the Tier-2 quiet window is bypassed. Freshness is established by those verification records — the response's wait-stamp (`waited 84s: rust-analyzer quiescence, tier2 rescan`, plus machine-readable phase IDs from the closed set fixed in constraints) reports COST and makes the wait auditable; it is not itself the proof. When freshness is unattainable — phase failure, writer-lease failure, server crash, never-quiesces, transport cap, user interrupt — the terminal response is an explicit non-fresh outcome in the inspect taxonomy (INTERRUPTED or PHASE-FAILED), naming what completed or what failed, and carries no counts presented as current. `scope=` guarantees narrowing of the RESULT set; it promises reduced WORK only for categories whose scoped execution path is defined (see open_questions 2), so no general cost-reduction claim is made for diagnostics yet.

## constraints

- **Honest reporting.** "Fresh" claims must be mechanically true. The verification tickets are: document version or epoch match, rust-analyzer quiescence where that server applies, stat-verified artifact identity, and writer-lease success for a rebuild. Wall-clock age and wait-stamp text are NOT freshness evidence. The protocol.rs tri-state convention (`success` + `complete` + named gap fields) remains the honesty convention for commands that are ALLOWED to be partial. Blocking `aft_inspect` is EXPLICITLY EXEMPT: it does not use partial-success at all. A FRESH terminal inspect response is the category payload transformed so that every requested category either carries mechanically verified data or the whole call is non-fresh, plus the wait-stamp; it contains none of `provisional`, `provisional_counts`, `pending_categories`, `stale_categories`, `scope_truncated`, `servers_pending`, `complete: false`, per-category `status: pending|stale|failed` sentinels, or stale-with-counts — the ban is on partial-result FIELDS generally, not on those names. The inspect-side emitters of those fields today are `summary_for` / `status_summary` / `computed_summary_for` (the stale-with-cached-payload branch that inserts `stale: true` while keeping counts) and `build_inspect_payload`; FRESH must not take those branches. This is an intended inspect terminal-shape change, not a silent reuse of today's JobOutcome summary.

- **The existing inspect deadline machinery is RETIRED, not relabelled (named conversion sites).** "Fresh is the only mode" is a change to specific code and downstream must be able to find it. Today `handle_inspect` bounds Tier-2 with `direct_tier2_wait_budget` plus `receive_direct_tier2` against an `Instant` deadline, treats `JobOutcome::Pending` / `JobOutcome::Stale` as a returnable result, and compensates afterwards with `ctx.request_tier2_refresh_pull()` and the `pending_tier2_paths` / `force_paths_completed` bookkeeping. Under fresh-only: NO wall-clock Tier-2 budget may remain on the blocking path, and a Tier-2 category that cannot be stat-verified or rebuilt-and-published is terminal shape (c) naming a phase from the closed ID set — never a Pending outcome plus a background refresh request. Whether the pending-paths bookkeeping survives for the background lane is an implementation choice; it may NOT be the mechanism by which a non-fresh category becomes part of a returned FRESH payload. Also named: the branch taken when `ctx.inspect_writer()` is false, which today falls back to `tier2_read_cached_readonly`. A reader-only daemon may serve Tier-2 ONLY where stat-verification proves the persisted artifact matches the current tree; if a rebuild is required and this process cannot take the writer lease, the call is (c) PHASE-FAILED, never readonly cached output presented as current.

- **Single terminal inspect response (RULED).** No deferred partial updates, no progress frames, no new NDJSON push machinery. The terminal wait-stamp is the only agent-visible cost report and lists only phases that actually ran (a zero-wait warm hit stamps that nothing was waited). Phase start/completion/duration/terminal-error are written server-side via the existing PhaseTrace path so humans can debug pathological waits without agents paying tokens.

RETIRED ON THE INSPECT PATH — the `direct_tier2_wait_budget` / `receive_direct_tier2` deadline truncation, any return of `JobOutcome::Pending` / `Stale` from a blocking inspect, and the readonly-cached Tier-2 fallback except where stat-verified, per the deadline-machinery constraint above.

- **Phase ID vocabulary is closed, shared, and semantically fixed.** `lsp_start`, `lsp_quiescence`, `tier2_rescan`, `callgraph_ready`, `stat_verification` are the ONLY machine-readable phase IDs, and their activity boundaries are fixed so the same failure cannot be labelled differently on two transports: `lsp_start` covers applicable-set resolution plus process startup to readiness; `lsp_quiescence` covers acceptance of a version/epoch-verified diagnostics snapshot and, where the server is rust-analyzer, its quiescence signal (a tsserver publish therefore also completes `lsp_quiescence` — the ID names the verification step, not the rust-analyzer mechanism); `callgraph_ready` covers cold-build admission, writer-lease acquisition, callgraph construction, and publication; `tier2_rescan` covers Tier-2 computation and publication after the callgraph is ready; `stat_verification` covers persisted-artifact identity verification with no rebuild. On a root with more than one applicable server, each phase entry carries the producer key alongside the ID so a mixed-language failure attributes to a server rather than to the root; the producer key is a DETAIL DIMENSION, not a new phase ID. A failure that occurs before any phase begins — root resolution failure, applicable-set resolution failure, missing executable discovered at resolution — fabricates no phase ID and uses an explicit preflight-failure form whose exact payload is GATE-1. Daemon shutdown names the in-flight phase where one exists and otherwise takes the same preflight form. Completed-phase lists contain only phases whose completion PhaseTrace recorded. Human wait-stamp prose may paraphrase; the machine field may not. Adding an ID, or moving a boundary between IDs, is a recorded amendment, not an implementation choice.

- **Blocking must not pin drain or executor lanes.** `handle_inspect` converts from today's Immediate `Response` to the deferred-response seam (`PendingResponses` / `DispatchOutcome::Deferred`, the machinery bash orchestration uses). The poll closure is OBSERVE-ONLY: it must not call diagnostics waits, rust-analyzer quiescence, callgraph cold build, or `ColdBuildLimiter::acquire_blocking`. LSP start, quiescence wait, and inspect-triggered builds run on dedicated background threads; LSP serialization stays on the existing manager/roots lock. The plugin requests a long `transportTimeoutMs` for inspect as bash wait mode does; the numeric budget cannot be committed until open_questions 1 fixes the ceiling.
  - SPIKE (open_questions 5): `PendingResponses` exposes only register / poll_ready / is_empty / drain_on_shutdown. There is no cancel-by-request-id seam, so clean per-request abort is NEW work, not reuse of the #188 pattern.
  - SPIKE: only the NDJSON drain tick and the shared polling seam have been read; the subc executor timer and the MCP-rides-subc path are UNVERIFIED for deferred responses of this duration (recorded as not inspected in the coverage manifest). All-transports parity is an end-to-end acceptance obligation, not an inference from the shared registry.

- **Terminal outcome taxonomy — a CLOSED set of three.** Every blocking inspect ends in exactly one of: (a) FRESH, with wait-stamp; (b) INTERRUPTED (user message / abort), stating which phases completed; (c) PHASE-FAILED, naming the phase (from the closed ID set, with producer key where applicable) and reason (server crashed, never quiesced, callgraph writer lease unavailable, cold build errored), or taking the preflight form when no phase had begun. THREE IS THE WHOLE SET: no fourth label — no `timed_out`, no `degraded`, no `partial` — may be introduced without a recorded amendment, because a fourth label is the re-entry route for stale-labelled data. The wire FIELD NAME and spelling carrying the label are deliberately unpinned until open_questions 1; downstream may depend on the three-way distinction now and on its encoding only after GATE-1 lands. (b) and (c) carry no counts presented as current and never reuse the provisional/pending vocabulary as a success path. DAEMON SHUTDOWN MID-WAIT IS BUCKETED, not left implicit: it is (c) PHASE-FAILED naming the in-flight phase with reason `daemon_shutdown`, delivered through the existing `drain_on_shutdown` path, until open_questions 1 rules otherwise; it may never be delivered as (a) and may never be dropped without a terminal frame. Until open_questions 1 rules otherwise, ANY requested category that cannot be made fresh fails the whole call as (c); no implementation may emit FRESH covering a subset of requested categories. Whichever ceiling is chosen, hitting it yields (c), never fresh-labelled data.

- **Applicable-server set is an explicit resolver output, snapshotted per inspect.** Before background work begins, inspect calls the existing root/server applicability resolver and SNAPSHOTS a set of `(canonical root, server kind, configuration identity)` records; that snapshot is the call's obligation for its whole life, and applicability discovered later applies to the next inspect. A server is applicable when repository language evidence and resolved project configuration select that kind. Process liveness does NOT affect applicability. `installed`, `configured`, `missing executable`, and `no applicable server for this root` are DISTINCT resolver outcomes and may not be collapsed — in particular, an unavailable executable may not be reclassified as inapplicable to make a cold inspect green. FRESH diagnostics require verified completion for every record in the snapshot. Terminal payloads for the missing-executable and empty-set cases remain GATE-1; neither may render zero diagnostics or any clean-state claim. Acceptance fixtures record the resolved set so no arm can pass by silently dropping a server kind.

- **On-demand LSP starts are bounded and reaped; the per-KIND bound is entailed, not an expansion.** At most one process of each applicable server kind (language / server-id) per requested root — NOT one process per root total. This is a derivation, recorded so it is not read as an unruled resource grab: fresh-only requires every requested category to be mechanically verified, and on a mixed TypeScript+Rust root a per-root single-process cap would leave one language permanently unverifiable, making every such root permanently non-fresh. The bound therefore follows from the freshness rule already ruled; what it does NOT license is two processes of the SAME kind for one root, unbounded fan-out across roots, or any start outside the snapshotted applicable set. Starts go through the existing manager / root-resolution / child-registry / process-group paths (per-process-group spawn + PDEATHSIG). The 54GB orphaned-analyzer incident is the cautionary bound — unreaped orphans, not a per-root process cap: no unreaped servers, and NO server starts on the passive path or the `health.digest` path — only on explicit inspect diagnostics requests and drill-down `sections`/`scope` requests. CANCELLATION IS CONDITIONAL ON open_questions 5: if true cancel-by-request-id is ruled, interrupt during startup, quiescence wait, limiter wait, or active build must leave no half-started server, and the acceptance process-table assertions stand; if detach-and-discard is ruled instead, that guarantee is WITHDRAWN and the process-table half of the interrupt/abort arms must be replaced by an explicit "server may continue warming" fixture before implementation. The two rulings must never be silently conflated. Idle-reap duration, startup-cancellation grace, and shutdown escalation are open_questions 6.

- **Cold-build admission.** An inspect-triggered callgraph/Tier-2 build waits for its `ColdBuildLimiter` permit ON A DEDICATED BACKGROUND THREAD, rechecking cancellation before and after acquisition, using the limiter's existing conditional-admission machinery with no new global knobs. STARVATION-FREE IS DEFINED OPERATIONALLY, not as an adjective: under sustained contention across the test window, (i) both classes (inspect-triggered and maintenance) record at least one admission, and (ii) no waiting request of either class is overtaken by more than one build of the other class before it is admitted. An implementation satisfying neither clause fails regardless of aggregate throughput. Failure to acquire the writer lease is terminal shape (c), never a silent stale read.

Tool-description changes (blocking-fresh inspect semantics; removal of deadline / `pending_categories` / repeated-polling guidance; removal of the shipped "Tier 1 scopes the scan; Tier 2 scans project-wide and applies scope as a result filter" sentence, which pre-commits a scoped-WORK story open_questions 2 has not ruled; alert-channel explanation) land on ONE release boundary; the prefix-cache bust bundles with that release.

- **Adversarially-audited ground fenced.** Lifecycle/epoch machinery, quiescence semantics, and artifact publication order are change-banned. #189/R42 supplies the quiescence oracle: a warming rust-analyzer's reports are not authoritative until its quiescence signal arrives. #188 supplies the abort pattern ONLY IF open_questions 5 rules true cancellation. ac5ffbfd supplies harness-scoped fleet suppression.

## acceptance_sketch

GATING NOTE (binds this whole sketch). Arms marked **[GATE-n]** are written against a ruling that has not landed and MUST NOT be implemented or silently dropped: they are rewritten or withdrawn when open_questions n is answered, and the answer is recorded in this section. An arm disappearing without a recorded ruling is a contract violation, not a scope trim.

**Inspect freshness**
- Cold authoritative inspect: from a fixture that EXPLICITLY installs and configures at least one applicable diagnostics server (the no-applicable-analyzer case is GATE-1, not this arm) with no running LSP process and evicted Tier-2 artifacts, invoke the real binary over NDJSON, subc, and MCP. Each call emits no intermediate frame and exactly one terminal success with quiescent diagnostics and fresh Tier-2 data, naming every phase actually awaited in human-readable text AND machine-readable phase IDs. The machine field is asserted against the CLOSED set `{lsp_start, lsp_quiescence, tier2_rescan, callgraph_ready, stat_verification}`: an unknown ID fails the test, so adding one forces a recorded amendment. Absence of `provisional`, `provisional_counts`, `pending_categories`, `stale_categories`, `scope_truncated`, `servers_pending`, `complete:false`, and per-category `status: pending|stale|failed` asserted by FIELD ABSENCE, not string match on prose. A mutation restoring the `summary_for` stale-with-cached-payload branch (counts plus `stale: true` on a FRESH inspect) must redden this arm. On a mixed-language fixture the arm requires verified diagnostics from EVERY applicable server kind, pinning the per-(root, server-kind) bound.
- Phase-boundary arms (pin the fixed activity boundaries, not just the spelling): a tsserver-only fixture completes `lsp_quiescence` on an accepted version-verified publish with no rust-analyzer present, proving the ID names the verification step rather than the rust-analyzer mechanism; a stat-verified warm Tier-2 hit records `stat_verification` and NOT `tier2_rescan`; a cold build records `callgraph_ready` before `tier2_rescan`. Moving an activity across an ID boundary must redden one of these.
- Producer-key arm: on a root with more than one applicable server, each phase entry carries the producer key alongside the ID, and a failure of ONE server attributes to that producer rather than to the root. The producer key is asserted to be a DETAIL DIMENSION — an implementation that encodes it by minting a new phase ID (e.g. a per-server variant) fails the closed-set assertion above.
- Preflight-failure arm: root resolution failure, applicable-set resolution failure, and a missing executable discovered at resolution each terminate with the explicit preflight form and FABRICATE NO phase ID — the completed-phase list is empty and the machine phase field carries no member of the closed set. An implementation that reports `lsp_start` for a server it never attempted must redden this arm. **[GATE-1]** the exact preflight payload is unruled; the arm asserts taxonomy, empty phase list, and absence of any clean-state or zero-diagnostics rendering only.
- Single-terminal-response shape: a frame-counting arm asserts exactly one agent-visible frame per inspect on each transport (no progress frames, no deferred partial updates), while the server-side PhaseTrace log for the same call contains the multi-phase timeline. Asserted in both directions: prose in the wait-stamp never appears as a separate frame, and PhaseTrace detail never appears in the agent payload. A companion arm asserts the completed-phase list contains only phases whose completion PhaseTrace actually recorded.
- Warm authoritative inspect: after warming the same canonical fixture, three dedicated-runner calls each complete within 5,000 ms wall clock (the bound is this number, asserted in CI; changing it requires a recorded amendment), preserve the authoritative shape, and prove via PhaseTrace and build instrumentation that no LSP process started and no callgraph or Tier-2 rebuild occurred. The wait-stamp for a zero-wait warm hit stamps that nothing was waited rather than omitting the stamp.
- Tree-mutation freshness: mutate a diagnostics-bearing file and a Tier-2 contributor after the prior snapshot; inspect must not return the old values. Mutation variants that accept the prior diagnostic version, prior artifact generation, or a stale cached payload must fail.
- Persisted restart reuse: daemon restart with an unchanged tree serves persisted Tier-2 counts as fresh after stat-verification alone, with instrumentation asserting the counts AND the absence of any rebuild or rescan.
- Retired-deadline arms (name the conversion sites so relabelling cannot pass): an instrumented arm asserts NO wall-clock Tier-2 budget is consulted on the blocking path — restoring `direct_tier2_wait_budget` / `receive_direct_tier2` deadline truncation must redden it — and that no `JobOutcome::Pending` or `JobOutcome::Stale` is ever converted into a returned FRESH payload, with or without a compensating `request_tier2_refresh_pull`. A reader-only-daemon fixture (`inspect_writer()` false) serves Tier-2 ONLY where stat-verification proves the persisted artifact matches the tree; where a rebuild is required and the writer lease cannot be taken, the call is (c) PHASE-FAILED and never `tier2_read_cached_readonly` output presented as current.
- Freshness-unattainable arms, each with its own distinct terminal shape and each BUCKETED so none can end without a terminal frame: (a) LSP child killed mid-wait → PHASE-FAILED; (b) server never reaches quiescence → PHASE-FAILED; (c) callgraph writer lease unavailable / cold build errors → PHASE-FAILED; (d) user-message detach → INTERRUPTED; (e) abort → INTERRUPTED; (f) daemon shutdown mid-wait → PHASE-FAILED with reason `daemon_shutdown`, naming the in-flight phase (or taking the preflight form when none had begun) and delivered via `drain_on_shutdown`. Each asserts the taxonomy label, a phase name drawn from the closed ID set where one applies, no counts presented as current, no reuse of the provisional/pending vocabulary on a success path, and pending-response state released. A fourth-label mutation (`timed_out`, `degraded`, `partial`) must redden the taxonomy arm. **[GATE-1]** the exact terminal payload per arm and whether any ceiling exists (transport cap, per-phase cap, none) is unruled; until it lands these arms assert taxonomy and field-absence only, the whole-call-failure default holds (one unfreshable requested category fails the call), and no `transportTimeoutMs` number is committed in a golden.
- Applicable-set snapshot arm: the resolver output is recorded in the fixture as `(canonical root, server kind, configuration identity)` records; the call's obligation is that snapshot for its whole life, applicability discovered mid-call applies only to the next inspect, and process liveness does not affect applicability. `installed`, `configured`, `missing executable`, and `no applicable server for this root` are asserted as DISTINCT resolver outcomes — a build that reclassifies an unavailable executable as inapplicable to make a cold inspect green reddens this arm. No arm may pass by silently dropping a server kind from the snapshot.
- **[GATE-5]** Process-table hygiene under interruption during startup, quiescence wait, limiter wait, and active build: under the TRUE-CANCEL branch, assert no newly started analyzer process group survives and no half-started server remains. Under the DETACH-AND-DISCARD branch, this half of each arm is WITHDRAWN and replaced by an explicit "server may continue warming and is later reaped" fixture. The two branches must never be conflated in one green run; the fixture names which branch it encodes. Under both branches an arm asserts at most one process per (root, server kind), no start outside the snapshotted applicable set, and no unreaped orphan after the call ends.
- Lane safety: a blocking inspect in flight does not stall other requests on any transport (concurrent-request arm), and an instrumented assertion proves no `acquire_blocking`, diagnostics wait, quiescence wait, or cold build occurs on the dispatch thread, an executor worker, or the poll closure — the poll closure is observe-only. Deferred delivery is verified INDEPENDENTLY per transport (NDJSON drain tick, subc executor timer, MCP-rides-subc), not inferred from the shared registry, since the latter two are recorded as uninspected.
- Admission fairness, operationalized so the word "starve" carries no weight: with a maintenance build queued continuously for the duration, run repeated inspect-triggered builds and assert (i) BOTH classes record at least one admission over the observation window, and (ii) no waiting request of either class is overtaken by more than one build of the other class before it is admitted. A policy that admits only inspect, or that lets maintenance overtake a waiting inspect build twice, reddens the arm. No new global knob may be introduced to make it pass.
- **[GATE-2]** `scope=` asserts RESULT narrowing only (the scoped result set is a subset of the unscoped one, with identical freshness guarantees). No wait-discount or reduced-work assertion is written, and no arm may depend on the deadline-truncating scoped path, whose `scope_truncated` / `servers_pending` outputs the fresh-only rule forbids.

**Release-boundary copy**
- Both plugin `aft_inspect` tool descriptions are asserted to describe blocking-fresh semantics, the wait-stamp, and `scope=` as result narrowing, and to explain the alert channel. Asserted ABSENT: "waits up to a short deadline", "complete: false", `pending_categories`, "use the next normal aft_inspect, not repeated polling", AND the currently shipped sentence "Tier 1 scopes the scan; Tier 2 scans project-wide and applies scope as a result filter", which pre-commits a scoped-WORK story open_questions 2 has not ruled. An arm asserts these changes land on ONE release boundary and that `health.digest` introduces no agent tool-description change.

## non_goals

- No redesign of `aft_inspect`'s category set, output format beyond freshness semantics, terminal non-fresh outcomes, and wait-stamps, or the drill-down `sections` contract.

- No new agent-visible progress or push channel: no progress frames, no deferred partial inspect updates, no new NDJSON push machinery. The terminal wait-stamp is the only agent-visible cost report.

Still open:

1. **[GATE-1] Wait ceiling and terminal failure payload (BLOCKING — "fresh is the only mode" is undefined without it).** Is there any ceiling on a blocking inspect beyond user interrupt — a transport hard cap, a per-phase cap, none at all? What exact terminal payload is returned for each of: missing analyzer, no applicable analyzer for the root, analyzer exit mid-wait, failure to reach quiescence, callgraph/Tier-2 build failure, writer-lease unavailable, daemon shutdown? 2. **[GATE-2] Scoped-diagnostics execution path (BLOCKING for the `scope=` cost claim).** Does `scope=` on one file didOpen just that file and await its publish, or must it establish full-root quiescence? This decides whether `scope=` is a wait discount or only a result filter, and which servers the on-demand bound permits starting. The existing scoped path is deadline-truncating (`scope_truncated`, `servers_pending`), which the fresh-only terminal rule forbids; whichever path is chosen must satisfy that. Until ruled, intent, tool copy, and the acceptance arm promise RESULT narrowing only, and no arm may depend on the truncating path.

5. **[GATE-5] Per-request cancel seam (BLOCKING for the interrupt process-table arms).** The deferred-response registry exposes only register / poll_ready / is_empty / drain_on_shutdown; there is no cancel-by-request-id today. Spike to size it, or rule that interrupt is detach-and-discard rather than true cancellation. The difference is observable in whether a half-started server keeps warming after the agent walked away, and it decides whether the acceptance process-table assertions stand (TRUE-CANCEL) or are replaced by an explicit warming-server-later-reaped fixture (DETACH-AND-DISCARD). The two branches must never be conflated in one green run. #188 is reuse only under the true-cancel branch.

6. **[GATE-6] Numeric lifecycle and rendering constants.** LSP idle-reap duration, startup-cancellation grace, shutdown escalation sequence for tracked process groups, which inspect or drill-down activity refreshes the idle deadline, and the maximum alert-line length asserted by the byte-goldens. Release-blocking constants, no config knobs. Until the line length is chosen the truncation arm asserts the property and pins the number afterwards. The warm-inspect 5,000 ms bound is already closed and is not this question.
